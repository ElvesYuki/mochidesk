# 桌宠 MVP 与像素形象迭代

## 2026-03-25

### 背景

项目方向已明确偏向“桌面宠物 / 灵动组件”，而不是带信息面板的桌面 Widget。

这一轮会话主要围绕两个主题推进：

- 桌宠窗口行为的可用性
- 小木藕像素形象的可识别度、可爱度和后续动作扩展空间

### 本次处理

- 将桌宠窗口收敛为小尺寸、透明、无边框、置顶、跳过任务栏的常驻窗口
- 将窗口拖拽、位置持久化、多显示器恢复、离屏修正和边缘吸附能力集中在 `src/lib/services/pet-window.ts`
- 窗口位置保存从“拖拽结束后保存”提升为窗口移动时实时保存
- 恢复窗口位置时，优先按上次所在显示器恢复；若位置已落到屏幕外，则自动拉回可见区域
- 基于 `temp/` 目录中的参考 HTML，逐步迭代出当前的小木藕像素豆芽主体
- 头顶豆芽旋转从 CSS 周期动画切换为 `requestAnimationFrame` 连续角度推进，并对目标速度做平滑逼近，避免切状态或周期边界时出现“跳转感”
- 红温态增强为更明显的热感表现，包括蒸汽、融化轮廓、脸部变化和更快的豆芽旋转
- 补充并持续迭代了左右手，目前已具备可见的豆豆手、轻微待机摆动和高光像素
- 调整了模拟系统状态节奏，拉长每段模拟状态的持续时间，降低状态切换的急促感
- 本轮过程中多次运行 `pnpm check` 和 `cargo check`，当前均可通过

### 当前结论

- 当前产品方向应继续保持为“仅保留角色形象的桌面宠物”，不回退为信息面板或滚动容器
- 角色视觉方向已经基本稳定为“像素小木藕 + 头顶持续旋转豆芽”
- 红温态不是单纯换色，而应表现为明显更忙、更热、更快的状态
- 手部已经成为后续动作扩展的正式入口，后面加电脑操作、点按、持物等交互时，应优先沿用现有左右手分组和旋转锚点
- 当前窗口行为已属于桌宠 MVP 的核心能力，后续应继续保持在 service 层，不回塞到页面组件中

### 后续建议

- 为真实系统监控能力预留更稳定的数据接口，替换当前纯模拟实现
- 为手部动作和道具扩展建立更明确的输入模型，例如 `idle / point / click / hold`
- 评估是否把 `MochiAvatar.svelte` 中的造型数据、状态计算和动作表现继续拆分
- 持续补充桌宠窗口的最小平台验证清单，覆盖透明、置顶、拖拽、吸附、多显示器与离屏恢复

## 2026-04-01 - Codex 状态链路首轮 review 修复

### 背景

在接入第一版 `Local Auto` Codex 状态读取后，对当前实现做了一轮代码审查，重点检查了事件语义识别、轮询成本和调试面板行为是否与文档一致。

审查中确认了 3 个需要立即收口的问题：

- `celebrate` 识别条件过宽，`stop` 这类泛化关键词可能误判为庆祝态
- 原生轮询每次都会从头读取并解析整个 rollout 文件，只为取最近少量事件
- 文档说明 `Alt + 双击` 的 Codex 调试循环会显示信息面板，但非开发态下实际没有显示

### 本次处理

- 收紧 `src-tauri/src/monitor/mod.rs` 中的 `celebrate` 匹配规则，避免把宽泛停止事件误判为庆祝
- 为 Codex 原生状态读取加入基于文件路径和修改时间的快照缓存
- 将 rollout 事件读取改为只保留最近固定数量的行，再做 JSON 解析，降低长会话下的无谓 I/O 和解析成本
- 调整 `src/lib/features/home/HomePage.svelte` 中调试面板的显示条件，让 Codex 调试循环单独开启时也能看到面板
- 同步收敛 `README.md` 中对原生关键词匹配的描述，避免文档暗示过宽的识别策略
- 运行 `pnpm check` 与 `cargo check`，当前均通过

### 当前结论

- Codex 状态识别的第一版规则仍然是保守启发式，但误判面已经比上一版更可控
- 原生轮询链路已经避免“每个轮询周期都全量解析整份 rollout 文件”的低效实现
- 调试行为和文档说明重新对齐，后续观察 Codex 状态差异时更容易直接验证

### 后续建议

- 继续基于真实 rollout 样本校准 `notice / celebrate / error / error_burst` 的识别条件，尽量减少纯关键词猜测
- 如果后续会话文件继续变大，可继续评估更细粒度的增量读取策略，而不只依赖修改时间缓存
- 在桌面端实际运行中补一轮 `pnpm tauri dev` 交互验证，确认调试角标和信息面板在小窗口尺寸下的可读性
