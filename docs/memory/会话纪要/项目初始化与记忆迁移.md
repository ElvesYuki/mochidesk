# 项目初始化与记忆迁移

## 2026-03-25

### 背景

仓库原有 `AGENTS.md` 只有较轻量的项目说明，缺少工程原则、检查清单和跨会话记忆机制。

同时仓库中存在一份来自旧项目的 `AGENTS1.md`，其中包含大量不适用于当前技术栈的 Python 企业框架规范，但其中的“简洁化与修复原则”“记忆协作规约”“提交规范”等工程方法可以迁移。

### 本次处理

- 将 `AGENTS.md` 扩写为 MochiDesk 版本
- 保留当前技术栈、目录边界、清理方向
- 迁移并重写工程原则、检查清单、提交规范、特殊规则
- 引入 `docs/memory/` 目录，建立项目记忆骨架
- 初始化 `index.md`、`待办.md` 及各目录说明文件

### 当前结论

- 只迁移与工程治理相关的内容，不迁移 Python / Vue / FastAPI / 数据库分层规范
- `docs/memory/` 作为当前仓库的长期协作上下文来源
- 后续每次会话应先读取 `index.md` 与 `待办.md`

### 后续建议

- 后续涉及真实系统监控、窗口能力封装、状态映射拆分时，把关键取舍补入 `决策/`
- 当 `HomePage.svelte` 继续演化时，应及时记录组件拆分方案，避免页面入口承担过多职责

## 2026-03-25 - HomePage 窗口逻辑拆分

### 背景

`HomePage.svelte` 同时承担了页面装配、系统状态驱动、窗口拖拽、位置恢复、边缘吸附和窗口移动监听，职责过于集中。

这和当前项目希望建立的目录边界不一致，也不利于后续替换真实系统监控或继续拆页面层逻辑。

### 本次处理

- 新增 `src/lib/services/pet-window.ts`
- 将 Tauri 运行时检测、窗口位置持久化、屏幕边界约束、边缘吸附和窗口移动监听迁入 service
- `HomePage.svelte` 改为只负责页面装配、拖拽中的 UI 状态绑定和系统状态驱动
- 运行 `pnpm check` 验证，检查通过

### 当前结论

- 窗口平台逻辑已从页面层收口到 service 层
- 当前拆分优先保证行为不变，属于职责迁移，不是交互重设计
- `HomePage.svelte` 的复杂度已经明显下降，但后续仍可继续拆分“系统状态驱动”和“页面布局样式”部分

### 后续建议

- 如果窗口行为继续增多，可把纯计算部分再下沉到 `utils/`，让 `pet-window.ts` 更聚焦平台交互
- 后续可评估是否补充窗口行为的最小验证清单，并写入 `docs/memory/决策/` 或 `docs/plans/`

## 2026-03-31 - AGENTS 协作规则补强

### 背景

本次根据外部 `AGENTS-bootstrap-pack.md` 重新审视仓库内的 `AGENTS.md`。

现有版本已经完成 MochiDesk 化迁移，但更偏项目说明与工程约束，缺少一部分通用而高价值的协作规则，例如“事实来源优先级”“先理解再改”“范围控制”“运行时分析”和“验证失败时的汇报方式”。

### 本次处理

- 保留现有 MochiDesk 项目定位、目录边界、MVP 约束和记忆协作规约
- 吸收 bootstrap pack 中与当前仓库相容的通用工程规则
- 为 `AGENTS.md` 新增“事实来源”“先理解再改”“范围控制原则”“运行时分析原则”“分析与汇报要求”等章节
- 在检查与验证部分补充“区分事实与推断”“不能验证时必须明确说明风险”等要求

### 当前结论

- `AGENTS.md` 现在既保留了 MochiDesk 的项目特化约束，也补齐了更通用的工程协作方法
- 这次同步不引入旧项目技术栈或通用模板里的无关结构，只吸收对当前仓库真正有帮助的工作方式

### 后续建议

- 后续如果 `README.md` 再次扩写，可继续按相同标准校对“现状 / 规划 / 推断”的表达边界
- 如果后续引入更多真实 Tauri 能力或多平台分支，建议把运行时差异进一步补充到 `决策/` 中
